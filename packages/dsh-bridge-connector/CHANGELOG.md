# Changelog

## 0.3.0 — 2026-11-02

**注入改成实时跟随（行为变更）**
- `/inject` 现在接受 `path` + `absPath`：只记路径，系统提示词每轮按 `mtime + size` 读磁盘最新内容
- 笔记改了，注入下一轮就跟着变，不用重新注——读到的是磁盘上的那一份，未保存的改动不会被注入
- 落盘只存路径（`~/.dsh-bridge/injections.json`），不存正文；正文每轮实时读
- 文件读不到时用最后一次读到的内容；从没读到过则明确写成「（文件读不到：xxx）」，不给空串
- 实时内容同样受 512KB/篇 预算约束，超了截断并注明
- 选区等不在文件里的内容仍作为「附加内容」拼在正文后，标成`【选中内容】`

**兼容性**
- 需要配套 Obsidian 侧 Bridge 插件 **0.3.0+**（它改成传路径）
- 旧客户端仍可传 `content`，走纯正文快照模式（老行为）

## 0.2.0 — 2026-10-31

首个公开版本。

**功能**
- 会话：列出 / 新建 / 向指定会话发消息
- 注入：最多 10 篇笔记挂进系统提示词段 `bridge:context`（order 250），单篇 512KB 预算，同标题覆盖
- 注入开关：落盘到 `~/.dsh-bridge/state.json`，DSH 重启后保持上次状态

**加固**
- 请求入口兜底：畸形请求行（如 `GET //`）回 400，不再把整个 DSH 进程打挂
- 请求体超限回 413（以前直接掐连接，调用方只看到 ECONNRESET）
- `/inject/clear` 收到坏 JSON 回 400，不再静默清空全部注入
- 单篇注入超 512KB 回 413（它在系统提示词里，每轮都要重发）
- 候选会话缺 `sessionId` 时回 409，不再 500 泄露内部异常

**删除**
- 没人消费的「按会话排队」通道（`take()` 无调用点，队列只进不出会漏内存），现在只有「当前注入」这一条语义
- `pre-step.mjs` 整份死代码及其测试
